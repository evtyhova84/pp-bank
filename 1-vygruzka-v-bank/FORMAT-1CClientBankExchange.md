# Формат выгрузки в банк: 1CClientBankExchange

Цель части 1: **на выходе — TXT-файл, который примет любой российский клиент-банк.**

## 0. Почему именно этот формат

`1CClientBankExchange` — открытый стандарт «1С» для обмена с системами «Клиент банка».
Его импорт поддерживают практически все российские банки: банку выгодно принимать то,
что умеет выгружать 1С. Файл — простой текст `ключ=значение`, без XML и JSON.

Имена файлов по стандарту:
- `1c_to_kl.txt` — **из 1С в банк** (это наш случай: мы отдаём платёжки)
- `kl_to_1c.txt` — из банка в 1С (выписки; нам не нужно)

Актуальная версия стандарта — **1.03**. Но в банковских инструкциях до сих пор массово
рекомендуют **1.02**, и часть банков на 1.03 капризничает. → Версия должна быть **параметром**,
по умолчанию `1.02`.

## 1. Физические свойства файла

| Свойство | Значение |
|---|---|
| Кодировка | **windows-1251** при `Кодировка=Windows`, **cp866** при `Кодировка=DOS` |
| Перевод строки | CRLF (`\r\n`) |
| Синтаксис строки | `Реквизит=Значение`, без пробелов вокруг `=` |
| Пустое значение | строка либо не выводится, либо выводится как `Реквизит=` |
| Многострочность | **нет**, значение всегда в одну строку |
| Разделитель дробной части | точка, всегда 2 знака: `12354.00` |
| Формат даты | `дд.мм.гггг` |
| Формат времени | `чч:мм:сс` |

⚠️ Кодировка — самая частая причина отказа импорта. UTF-8 банк не примет.

## 2. Структура файла

```
1CClientBankExchange          ← строка-маркер, БЕЗ знака "="
<шапка>
<секция документа>            ← повторяется N раз, по одной на платёжку
КонецФайла
```

Секция выписки `СекцияРасчСчет … КонецРасчСчет` — только для направления «из банка в 1С».
**В нашем файле её быть не должно.**

## 3. Шапка

| Реквизит | Обяз. | Значение у нас |
|---|---|---|
| `ВерсияФормата` | да | `1.02` (параметр профиля банка) |
| `Кодировка` | да | `Windows` |
| `Отправитель` | нет | наше название системы |
| `Получатель` | нет | пусто или название банка |
| `ДатаСоздания` | нет | дата формирования файла |
| `ВремяСоздания` | нет | время формирования |
| `ДатаНачала` | **да** | мин. дата документа в пачке |
| `ДатаКонца` | **да** | макс. дата документа в пачке |
| `РасчСчет` | да | счёт плательщика; строк может быть несколько |
| `Документ` | да | `Платежное поручение` |

## 4. Секция документа

Начало: `СекцияДокумент=Платежное поручение`, конец: `КонецДокумента`.

### 4.1. Сам документ
| Реквизит | Обяз. | Формат |
|---|---|---|
| `Номер` | **да** | строка |
| `Дата` | **да** | дд.мм.гггг |
| `Сумма` | **да** | руб.коп, точка |

### 4.2. Плательщик
| Реквизит | Обяз. | Комментарий |
|---|---|---|
| `ПлательщикСчет` | **да** | 20 знаков |
| `Плательщик` | да | склейка: `ИНН <инн> <наименование>` |
| `ПлательщикИНН` | **да** | 10 или 12 знаков |
| `ПлательщикКПП` | для бюджета | 9 знаков |
| `Плательщик1`…`Плательщик4` | да | 1 — наименование, 2–4 — доп. строки |
| `ПлательщикРасчСчет` | да | дублирует `ПлательщикСчет` |
| `ПлательщикБанк1` | да | название банка |
| `ПлательщикБанк2` | да | город банка |
| `ПлательщикБИК` | **да** | 9 знаков |
| `ПлательщикКорсчет` | **да** | 20 знаков |

### 4.3. Получатель — зеркально
`ПолучательСчет`, `Получатель`, `ПолучательИНН`, `ПолучательКПП`,
`Получатель1`…`Получатель4`, `ПолучательРасчСчет`,
`ПолучательБанк1`, `ПолучательБанк2`, `ПолучательБИК`, `ПолучательКорсчет`

### 4.4. Реквизиты платежа
| Реквизит | Комментарий |
|---|---|
| `ВидПлатежа` | `Почтой` / `Телеграфом` / `Срочно` / пусто (пусто = электронно) |
| `ВидОплаты` | код вида операции ЦБ; для платёжки — `01` |
| `Очередность` | очерёдность платежа, обычно `5` |
| `Код` | УИН, до 25 знаков; для обычной оплаты поставщику — `0` |
| `КодНазПлатежа` | поле 20 «Наз. пл.», код вида дохода 1–5 по 229-ФЗ. Организации и ИП — пусто; физлицу, самозанятому в том числе, — `1` ([PRAVILA-samozanyatye.md](../PRAVILA-samozanyatye.md)) |
| `СрокПлатежа` | дд.мм.гггг, необязательно |
| `НазначениеПлатежа` | полный текст одной строкой |
| `НазначениеПлатежа1`…`6` | тот же текст, разбитый по строкам |

⚠️ `НазначениеПлатежа` и `НазначениеПлатежа1` в реальных файлах дублируются —
выводим оба, иначе часть банков теряет назначение.

### 4.5. Только для платежей в бюджет
`СтатусСоставителя` (2 зн.), `ПоказательКБК` (20 зн.), `ОКАТО` (сюда пишется **ОКТМО**),
`ПоказательОснования` (напр. `ТП`), `ПоказательПериода` (напр. `МС.04.2015`),
`ПоказательНомера`, `ПоказательДаты`, `ПоказательТипа` (поле 110 отменено, пишем `0`).

При бюджетном платеже `ПлательщикКПП` и `ПолучательКПП` становятся обязательными.

## 6. Что должен делать наш генератор

1. Принять: реквизиты плательщика (один счёт на пачку) + список распознанных счетов.
2. Посчитать `ДатаНачала` / `ДатаКонца` по документам пачки.
3. Пронумеровать платёжки (сквозная нумерация — параметр: с какого номера начинать).
4. Собрать `НазначениеПлатежа` по шаблону, включая НДС:
   `Оплата по счету № {номер} от {дата}. В т.ч. НДС {ставка}% — {сумма} руб.`
   либо `Без НДС`, если ставка не выделена.
5. Отформатировать суммы (2 знака, точка) и даты (дд.мм.гггг).
6. Записать в **windows-1251** с CRLF, имя файла `1c_to_kl.txt`.

## 7. Профили банков

Универсальность даёт не «один файл на всех», а ядро + тонкие профили в `profili-bankov/`.
Что различается между банками:
- версия формата (`1.02` / `1.03`);
- кодировка (`Windows` / `DOS`);
- выводить ли необязательные пустые строки или опускать их;
- строгость к `Код` (УИН): `0` или пусто;
- обрезка длины `НазначениеПлатежа` (обычно 210 знаков).

Профиль — маленький файл настроек; ядро генератора одно.

## 8. Что проверить на живом банке

- [ ] принимает ли банк `ВерсияФормата=1.03` или требует `1.02`;
- [ ] нужен ли `Код=0` или можно пустым;
- [ ] нужны ли `Плательщик2..4` / `Получатель2..4`;
- [ ] предельная длина назначения платежа;
- [ ] реакция на несколько документов в одном файле (пачка).
