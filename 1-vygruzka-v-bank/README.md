# Часть 1 — выгрузка в банк

Пачка счетов → один файл `1c_to_kl.txt` формата `1CClientBankExchange` для клиент-банка.

Зависимостей нет, нужен только Python 3.10+.

## Запуск

```bash
cd 1-vygruzka-v-bank

# посмотреть результат, ничего не записывая и не двигая нумерацию
python -m generator --payer primer/payer.json --invoices primer/invoices.json --dry-run

# сформировать файл
python -m generator --payer primer/payer.json --invoices primer/invoices.json --date 26.08.2026
```

Флаги: `--out` (куда писать), `--date` (дата платёжек), `--profile` (профиль банка),
`--registry` (журнал нумерации), `--dry-run`.

## Что внутри

| Файл | Отвечает за |
|---|---|
| `generator/models.py` | входные данные: плательщик, счёт, профиль банка; разбор дат и сумм |
| `generator/validate.py` | контрольные суммы ИНН и счетов, ограничения ЦБ на номер, проверка кодировки |
| `generator/numbering.py` | счётчики номеров и журнал закреплённых номеров |
| `generator/export.py` | сборка самого файла |
| `generator/cli.py` | командный интерфейс |
| `profili-bankov/` | различия между банками |
| `primer/` | демо-данные (реквизиты вымышленные, но с валидными контрольными суммами) |

## Что уже сделано

- Файл формата `1CClientBankExchange` 1.02/1.03, **cp1251 + CRLF**, без секции выписки.
- Нумерация по решению из [RESHENIE-numeratsiya.md](RESHENIE-numeratsiya.md):
  свой диапазон, счётчик по *(плательщик, счёт, год)*, номер выдаётся при выгрузке,
  повторная выгрузка даёт те же номера, запрещённые ЦБ номера перешагиваются.
- Проверка реквизитов **до** записи файла: контрольная сумма ИНН, контрольный ключ
  расчётного и корр. счёта по БИК, формат КПП, ограничения на номер платёжки.
  При ошибке файл не пишется вообще.
- Назначение платежа собирается само, с НДС или «Без НДС», с обрезкой до 210 знаков
  и заменой типографских символов, которых нет в cp1251.
- Предупреждение, если счёт уже выгружался раньше — защита от двойной оплаты.
- Журнал `reestr-nomerov.json`: какой номер какому счёту достался и в каком файле ушёл.

## Тесты

```bash
python -m unittest discover -s tests
```

28 проверок: разбор сумм из счёта, контрольные суммы, идемпотентность нумерации,
перешагивание запрещённых номеров, структура и байты выходного файла.
