# Выложить сервис на внешний тест

Пошагово: от пустого сервера до логинов у сотрудников. Ориентировочно два часа,
из которых час — ожидание (заказ сервера, обновление DNS).

Здесь только про **вынос на сервер и раздачу людям**. Как сервис устроен и
что он умеет — [servis/README.md](../servis/README.md).

---

## Что выбрано и почему

| | Решение | Почему так |
|---|---|---|
| Площадка | VPS с **Windows Server** у российского хостера | На Windows работает встроенный `Windows.Media.Ocr` — основной движок распознавания сканов: на эталоне 33 ключевых поля из 40 против 24 у Tesseract. На Linux остался бы только Tesseract |
| Где | Российский хостер (Timeweb Cloud, Selectel, Reg.ru, Yandex Cloud) | Через сервис ходят банковские реквизиты и ФИО сотрудников |
| HTTPS | Caddy, сертификат Let's Encrypt | **Обязателен, не по желанию**: кука сессии выдаётся с флагом `secure`, по голому HTTP браузер её не вернёт и войти будет физически нельзя |
| База | SQLite как есть | Пачек в день — десятки. Один файл проще бэкапить |

---

## Шаг 1. Заказать сервер

Минимум для теста впятером:

- **2 ядра, 4 ГБ памяти, 40 ГБ диска**, Windows Server 2022 или 2025.
  Распознавание — единственное, что грузит процессор; на 4 ГБ пачка в полсотни
  счетов разбирается спокойно.
- Ориентир по цене: 1000–1800 ₽/мес, лицензия Windows обычно уже в цене.
- Хостер выдаст IP-адрес, логин `Administrator` и пароль.

**Сразу после заказа, до всего остального:**

1. Смените пароль администратора на длинный. Windows-сервер с внешним IP
   начинают перебирать по RDP в первые же часы.
2. Ограничьте RDP своим адресом — в панели хостера это обычно «Файрвол»
   или «Группы безопасности»: разрешить порт 3389 только с вашего IP,
   остальным закрыть. Порты 80 и 443 оставить открытыми для всех.

## Шаг 2. Подключить домен

У вас домен уже есть — заведите поддомен, например `scheta.вашдомен.ru`:

- в панели, где лежит домен, добавьте **A-запись**: имя `scheta`,
  значение — IP сервера;
- подождите, пока разойдётся. Обычно 10–30 минут. Проверка с вашей машины:

  ```powershell
  Resolve-DnsName scheta.вашдомен.ru
  ```

  Пока в ответе не появится IP сервера, дальше идти нет смысла: Caddy не сможет
  получить сертификат, потому что Let's Encrypt проверяет домен обращением к нему.

## Шаг 3. Перенести проект на сервер

На **своей** машине, из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File razvertyvanie\sobrat.ps1
```

Получится `pp-bank-<дата>.zip` (~30 МБ) рядом с папкой проекта. Рабочие данные
в него не попадают: на сервере база заводится с нуля.

Подключитесь к серверу по RDP (`mstsc`, адрес и пароль от хостера), скопируйте
архив внутрь окна RDP обычным перетаскиванием и распакуйте в `C:\pp-bank` —
так, чтобы получилось `C:\pp-bank\servis\app\main.py`.

## Шаг 4. Установка

На **сервере**, в PowerShell «от имени администратора»:

```powershell
powershell -ExecutionPolicy Bypass -File C:\pp-bank\razvertyvanie\ustanovka.ps1 -Domen scheta.вашдомен.ru
```

Скрипт по шагам: Python и библиотеки → русский язык для встроенного OCR и
Tesseract → служба `SchetaVBank` → Caddy с сертификатом → правила брандмауэра →
ночная копия базы. Ставится Python (PSF), Tesseract (Apache 2.0), NSSM
(public domain), Caddy (Apache 2.0) — AGPL нет ни в одном, отдавать сервис
сторонним организациям это не мешает.

Скрипт можно запускать повторно: уже сделанное он пропускает.

Если `winget` на сервере нет (бывает на голом Windows Server) — поставьте
«App Installer» из Microsoft Store либо четыре программы вручную:
[Python](https://www.python.org/downloads/windows/),
[Tesseract](https://github.com/UB-Mannheim/tesseract/wiki),
[NSSM](https://nssm.cc/download),
[Caddy](https://caddyserver.com/download), — и запустите скрипт снова, он
доделает остальное.

## Шаг 5. Первый вход и настройка

1. Откройте `https://scheta.вашдомен.ru` — сервис сам предложит страницу
   «Первый запуск» и заведёт **вас** администратором.
   Эта страница работает ровно один раз: как только появился первый
   пользователь, она отдаёт на обычный вход. Так что сделайте это сразу,
   не откладывая на «завтра покажу коллегам».
2. **Плательщики** → заведите организацию, от чьего имени будете платить, и её
   расчётный счёт. Реквизиты не набирайте руками — загрузите документ этой
   организации (платёжку, выписку, файл обмена), сервис прочитает сам.
3. **Сотрудники** → логины тестировщикам, роль **оператор**.
   Администратор нужен только вам: оператору хватает грузить счета и забирать
   файл, а справочники и люди — не его дело.

## Шаг 6. Проверить перед тем, как звать людей

Пройдите весь путь сами, на настоящих счетах:

- [ ] зашли по `https://`, замок в адресной строке без предупреждений;
- [ ] загрузили пачку счетов, разбор прошёл;
- [ ] счета, выставленные не на вашу организацию, помечены — так и должно быть;
- [ ] скачали файл для клиент-банка;
- [ ] **открыли этот файл в клиент-банке.** Это единственная непроверенная
      часть всего проекта: формат собран по спецификации и покрыт тестами, но
      живой банк его ещё ни разу не принимал. Если что-то не так — выяснится
      здесь, а не у пятерых сотрудников сразу;
- [ ] вышли и зашли снова — сессия держится;
- [ ] перезагрузили сервер (`Restart-Computer`) и убедились, что сервис поднялся
      сам: `Get-Service SchetaVBank, caddy` — обе `Running`.

## Шаг 7. Раздать сотрудникам

Каждому: адрес, логин, пароль (разными сообщениями — пароль не в том же чате,
где адрес) и памятку [PAMYATKA-sotrudniku.md](PAMYATKA-sotrudniku.md).
Попросите сменить пароль при первом входе.

Соберите с них замечания в одном месте — таблица, чат, что угодно, лишь бы
не пять разных личных переписок. Что просить писать — в конце памятки.

## Дальше, когда сервис уже работает

### Обновить код

На своей машине `sobrat.ps1`, на сервере распаковать поверх `C:\pp-bank`
(папку `servis\dannye` архив не трогает — там база) и:

```powershell
Restart-Service SchetaVBank
```

Без перезапуска службы люди продолжат видеть старое поведение и напишут,
что «ничего не изменилось».

Проект теперь под git, так что есть путь короче — если завести для него
приватный репозиторий (GitHub, GitVerse, Gitflic — любой, лишь бы приватный:
в истории комментарии к банковской логике, но не сами платежи). Тогда
на сервере один раз `git clone`, а обновление — две команды:

```powershell
cd C:\pp-bank; git pull
Restart-Service SchetaVBank
```

`servis\dannye` в репозиторий не входит, база от `git pull` не пострадает.

### Посмотреть, что происходит

```powershell
Get-Service SchetaVBank, caddy                              # живы ли
Get-Content C:\pp-bank\servis\dannye\zhurnal\sluzhba.log -Tail 50
Get-Content C:\pp-bank\servis\dannye\zhurnal\caddy.log -Tail 50
```

Внутри сервиса есть свой журнал действий — раздел **Журнал**, кто что делал.

### Копии

Ночью в 3:00 задание `Scheta-kopiya` кладёт копию в `C:\pp-bank\kopii`
(база — каждую ночь, исходные счета — по воскресеньям, храним 14 копий).
Проверить: `Get-ChildItem C:\pp-bank\kopii`.

**Копия лежит на том же сервере — это не резервная копия, а полумера.**
Раз в неделю уносите папку наружу: к себе на машину или в облако.
Главное в ней — `servis.db`: там журнал нумерации платёжек, и если он
потеряется, счётчик начнётся заново и в банк уйдут номера, которые уже
использованы.

### Если сервис не открывается

| Что видно | Где смотреть |
|---|---|
| Браузер не находит сайт | A-запись домена: `Resolve-DnsName scheta.вашдомен.ru` |
| «Не удалось установить соединение» | `Get-Service caddy`; порты 80 и 443 в файрволе хостера |
| Ошибка сертификата | `caddy.log`: Let's Encrypt не смог достучаться до домена — чаще всего закрыт порт 80 |
| Страница 502 | Сервис лежит: `Get-Service SchetaVBank`, дальше `sluzhba.log` |
| Вход не проходит по кругу | Зашли по `http://` вместо `https://` — кука `secure` не возвращается |
| Сканы читаются мусором | `Get-WindowsCapability -Online -Name "Language.OCR*"` — стоит ли русский язык |

## Что стоит знать заранее

**Тест на живых деньгах.** Файл платёжек ни разу не принимался настоящим
клиент-банком (единственная попытка в сентябре 2026 дала список ошибок, который
с нашим файлом не сходится — вероятно, в банк ушёл другой файл). Первую неделю
пусть каждый файл перед загрузкой в банк смотрит человек, который умеет читать
платёжку глазами.

**Слишком тяжёлые файлы.** Предел — 25 МБ на файл и 600 МБ на пачку; у фото
с телефона 25 МБ бывает. Такой файл в пачку не берётся, но и не пропадает:
он виден строкой «не принят» с объяснением, а над списком написано, сколько
файлов не приняли. Счёт из этой пачки придётся пересохранить полегче
и загрузить отдельно.

**Вторая ступень распознавания выключена** — и пусть остаётся выключенной.
Это единственное место, где документ уходит за пределы сервера; включать её
на внешнем тесте с чужими счетами не надо.
