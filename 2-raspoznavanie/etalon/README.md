# Эталон для слоя распознавания сканов

Здесь лежит то, что **должен** выдать будущий OCR-слой на конкретных файлах.
Это приёмочный тест: пока распознавание не воспроизведёт эти значения — оно не готово.

## Как эталон получен

Реквизиты вычитаны со сканов вручную и проверены нашими же контрольными суммами:
ИНН, КПП, БИК, расчётный счёт, корр. счёт, а также сходимость ставки НДС с суммами.
**24 независимые проверки, все сошлись** — значит цифры прочитаны верно, а не «похоже».

Это и есть главный приём для сканов: реквизиты счёта самопроверяемы. Ошибка в одной
цифре почти наверняка ломает контрольную сумму и не проходит молча.

опознаётся по ключам счетов, поля склеиваются из двух движков. **Все четыре
скана прошли контрольные суммы и попали бы в файл для банка** без правки
реквизитов: 50 из 60 полей эталона совпали буквально, расхождения только

## Что эти счета добавили к требованиям

- **Номер счёта не всегда число.** `1/ПМ` — буквы и дробь. Поле 3 платёжки должно быть
  цифровым, но это номер *счёта поставщика*, он идёт только в назначение платежа.
  Наш номер платёжки к нему отношения не имеет — конфликта нет.
- **Ставка НДС 5%** (УСН с пониженной ставкой). Уже поддерживается: она есть
  в списке допустимых при выводе ставки из сумм.
- **Третий плательщик** — ООО «ПОСЛЕДНЯЯ МИЛЯ», ИНН 5029282981, КПП 502901001.
  Ему понадобится свой файл реквизитов и свой счётчик номеров платёжек.
