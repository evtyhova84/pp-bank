# Сервис: счета → файл для клиент-банка

Сотрудник открывает сайт, загружает пачку счетов (PDF, сканы, фото), проверяет
распознанное на экране и скачивает `1c_to_kl.txt` для клиент-банка.

Внутри — те же части 1 и 2 проекта, что работают из командной строки. Сервис
их не дублирует, а вызывает: правила формата банка, проверки реквизитов и
нумерация живут в одном месте.

## Что уже есть

- окно запуска с кнопками вместо командной строки, первый вход — сразу в браузере;
- вход по логину и паролю, три роли: **оператор** грузит счета и забирает файл;
  **бухгалтер** — то же плюс справочники (плательщики, их счета, получатели);
  **администратор** — плюс сотрудники и пароли. Роль выбирается на странице
  «Сотрудники» и действует сразу, без перезахода; себе роль сменить нельзя —
  вернуть её было бы некому;
- справочник плательщиков с проверкой реквизитов контрольными суммами;
- **несколько расчётных счетов у одной организации** (Точка, Сбербанк): при
  загрузке выбирается, с какого платить; нумерация платёжек у каждого счёта своя;
- **справочник получателей**, который набирается сам из разобранных счетов:
  видно, кому и сколько раз платили, а недочитанные поля берутся оттуда;
- **НДС из истории получателя**: счёт, который про НДС молчит, не идёт
  с вопросом, если этому получателю уже платили без НДС или со ставкой;
  ставка на экране проверки выбирается из списка, выбор запоминается;
- **назначение платежа с описанием**: «за что платим» берётся из позиций
  счёта и ужимается в предел банка так, чтобы хвост про НДС уцелел;
- **плательщик по счетам**: пачка, загруженная не под той организацией,
  переназначается одной кнопкой, а неизвестный плательщик заводится
  с уже заполненными наименованием, ИНН и КПП;
- заполнение реквизитов плательщика из старой платёжки — двадцатизначные счета
  не надо набивать руками;
- **сканы и фото**: два локальных движка, и если первый не сошёлся по
  контрольным суммам, счёт перепроверяется вторым;
- **пачками**: за раз до 500 счетов, один файл на всю пачку — по платёжке
  на каждый счёт; распознавание идёт в фоне и в несколько потоков;
- **дубли не оплачиваются дважды**: один и тот же счёт, попавший в пачку
  повторно или уже оплаченный раньше, исключается с пометкой;
- экран проверки: сводная таблица по всей пачке, правка полей руками;
- счета с замечаниями в файл не попадают — сначала их смотрит человек;
- нумерация платёжек в базе: два сотрудника одновременно не получат один номер,
  а повторно загруженный счёт получит тот же номер, что и в прошлый раз;
- журнал: кто, когда, какие номера и на какую сумму выгрузил;
- защита от подбора пароля: несколько неудач подряд закрывают вход по этому
  логину на 15 минут, отдельный счётчик — по адресу;
- разделение организаций: пользователи одной компании не видят данные другой.

## Быстрый запуск (проверить у себя)

Двойным щелчком по **`zapusk.bat`** в корне проекта. Откроется маленькое окно
программы: строка состояния и три кнопки — «Запустить», «Открыть в браузере»,
«Остановить». Сервис поднимается сам, браузер открывается сам, недостающие
библиотеки доустанавливаются сами. Чёрного окна с командами нет.

**Первый запуск**: браузер покажет страницу «Первый запуск» — впишите имя,
логин и пароль. Больше ничего не спрашивается: организации, за которые вы
платите, заводятся потом и выбираются в момент платежа.

Окно можно свернуть — сервис работает, пока оно открыто. Закрыть окно =
остановить сервис.

То же самое из командной строки (для сервера):

```bat
cd C:\Projects\pp-bank
pip install -r servis\requirements.txt
python -m servis               :: http://127.0.0.1:8000, дальше вход в браузере
```

Дальше в интерфейсе: **Плательщики** → завести организацию и её расчётный счёт,
потом **Пачки** → «Загрузить счета».

### Реквизиты плательщика — не набирать руками

На странице «Плательщики» есть **«Заполнить из старой платёжки»**. Подойдёт:

- файл выгрузки в клиент-банк или выписка из него (`1c_to_kl.txt`, `kl_to_1c.txt`) —
  это точный источник, реквизиты лежат готовыми полями;
- само платёжное поручение в PDF или снимком — разбирается как счёт.

Реквизиты подставятся в форму, но **не сохранятся сами**: их проверяют
контрольными суммами и показывают человеку. Сохраняет — человек.

Разбор формы 0401060 учитывает, что клетки печатаются рядами и в одну строку
попадает содержимое соседней: название банка приезжает вместе с БИК, а
наименование ИП не влезает в строку и переносится. Хвосты срезаются по меткам
(«БИК», «Сч. №», «ИНН», «КПП»), название собирается из подряд идущих строк,
город отделяется от банка — в файле для клиент-банка это разные поля.

**В платёжке две стороны, и ваша может быть любой.** В своей исходящей
платёжке организация — плательщик. Но подтверждение поступления, которое
выгружают из банка (так делает Альфа-Банк), — это платёжка, где вы
**получатель**, а плательщик — ваш заказчик. Поэтому читаются обе стороны,
а какая ваша — решается по признакам: в файле обмена это счёт из шапки
(`РасчСчет`), в PDF — банк, выдавший документ: его БИК стоит в отметках внизу
и совпадает с банком одной из сторон. Признаков нет — берётся плательщик.
Вторая сторона в любом случае под рукой: кнопка «Это не мы — взять …»
переставляет реквизиты в форме без повторного чтения файла.

**Длина ИНН разная:** у организации десять знаков, у ИП и физлица — двенадцать.
Проверяются двенадцать, и только потом десять, иначе от ИНН предпринимателя
откусывались бы первые десять цифр. КПП у ИП нет; в платёжке он печатается
нулём, и это не значение, а его отсутствие.

**Подпись клетки — только подсказка, решают контрольные суммы.** Искать значение
рядом с подписью можно, только если они рядом стоят, а в бланке это не так:
номера печатают вразрядку по клеткам (`6 1 6 1 2 5 8 5 5 3 2 6`), подпись «ИНН»
уезжает в свою строку, соседние клетки слипаются. Поэтому реквизит опознаётся
по себе самому — у ИНН, БИК и счетов есть контрольные суммы.

Отдельно про БИК: девять цифр сходятся у слишком многих чисел, в том числе
у начала ИНН. Поэтому БИК выбирается не первым подходящим, а тем, **под которым
сходятся ключи расчётного и корр. счетов** — чужой БИК их не подтвердит.

### Несколько счетов у одной организации

Если у организации счета в разных банках, они заводятся как **счета одного
плательщика**, а не как разные плательщики: у каждого своя метка («Точка»,
«Сбербанк»), свои реквизиты банка и свой начальный номер платёжек. При загрузке
пачки выбирается, с какого счёта платить.

Нумерация ведётся по ключу *(плательщик, счёт, год)* — счётчики банков
не пересекаются. Начальные номера у счетов лучше развести (900001 и 800001),
чтобы по номеру платёжки сразу было видно, из какого банка она ушла.

### Как обрабатывается пачка

Бухгалтер выбирает счёт плательщика, дату и указывает **все счета сразу** —
хоть один, хоть пятьсот. Дальше:

1. Файлы загружаются, браузер сразу свободен: распознавание идёт в фоне,
   страницу можно закрыть и вернуться позже.
2. Документы разбираются параллельно (по умолчанию в 4 потока — на пачке
   из сотни сканов это разница между минутами и получасом).
3. Ищутся дубли: тот же счёт дважды в пачке или уже оплаченный раньше.
4. На экране — сводная таблица по всей пачке и разбор по каждому счёту.
5. Одна кнопка «Сформировать файл» → **один** `1c_to_kl.txt` со всеми платёжками.

Пределы меняются переменными: `PP_PREDEL_PACHKI` (500 счетов),
`PP_PREDEL_PACHKI_MB` (600 МБ на пачку), `PP_POTOKOV` (потоков распознавания).
Предел в 500 стоит не из-за скорости разбора, а из-за человека: просмотреть
глазами тысячу счетов за один присест всё равно не получится.

Файл, который в пределы не уложился (тяжелее 25 МБ или переполнил пачку),
не пропадает молча, а становится строкой в пачке с пометкой «не принят»
и объяснением, сколько он весит. Раньше он исчезал беззвучно: бухгалтер
грузил полсотни счетов, получал сорок восемь и не мог понять, каких двух
не хватает. На диск такой файл не сохраняется, исходника у него нет.

### Дубли

Один счёт — одна платёжка. Дубль ловится по совокупности: получатель, его
расчётный счёт, номер и дата счёта, сумма. Проверяются два случая:

- **дважды в одной пачке** — счёт отсканировали повторно, прислали и почтой,
  и в мессенджере;
- **уже выгружался раньше** — по журналу нумерации.

Такие документы не удаляются, а исключаются из выгрузки с пометкой на экране:
вернуть в пачку можно одной кнопкой. Решает человек — вдруг это действительно
два разных счёта с совпавшими реквизитами.

### Справочник получателей

Заполняется сам: каждый разобранный счёт добавляет получателя с его реквизитами
и считает, сколько счетов от него было и сколько раз ему заплатили.

Из справочника **дописываются только те поля, которые не адресуют деньги** —
КПП, город банка, название банка, корр. счёт, полное наименование. Расчётный
счёт, ИНН и БИК не подставляются никогда: их берут только из самого документа.
Подстановка всегда помечается заметкой на экране проверки.

Единственное поле, которое справочник вправе **заменить**, а не только дописать, —
наименование. Со скана оно регулярно приезжает мусором («(Иттолнитель): Москва,
пр-кт…»), при этом ИНН и счёт читаются верно. Если по этим реквизитам уже
платили, имя получателя известно точно. Пока не платили — такой счёт идёт
человеку: мусорное имя в поле «Получатель» банк вправе отклонить.

### НДС, которого в счёте нет

Счёт ИП на УСН часто не говорит про НДС ни слова. Парсер честно ставит
`vat_status = unknown`, и раньше каждый такой счёт шёл человеку с вопросом.
Теперь справочник получателей помнит, как получатель работает с НДС по
последнему разобранному или поправленному счёту: «без НДС» либо ставка.
Молчащий счёт знакомого получателя получает это значение **с заметкой** и
проходит чистым; для ставки сумма НДС считается от итога и тоже помечается —
сверить со счётом остаётся за бухгалтером.

На экране проверки ставка — выбор из списка: «Без НДС», 22, 20, 10, 7, 5 %.
Выбрали ставку и не вписали сумму — сумма посчитается от итога. Выбор
запоминается за получателем. Счёт с неопределённым НДС в файл не уходит:
иначе в назначении платежа оказалось бы «Без НДС» наугад.

### Назначение платежа: за что платим

В назначение идёт не только «Оплата по счету № N от Д», но и **за что** —
наименования позиций из таблицы счёта. Парсер вытаскивает их без цен и
количеств (переносы наименования на соседние строки склеиваются, порядковые
номера позиций отличают новую позицию от номера дома в адресе доставки),
а генератор укладывает в предел банка — 210 знаков — так, чтобы хвост про
НДС уцелел. Не влезло — обобщается: у шести «Заправка картриджа Kyocera …»
берётся общее начало и пишется «заправка картриджа Kyocera (6 позиций)»,
у разнородных позиций перечисляется, сколько влезло, и добавляется «и др.».

Поле «За что платим» правится руками на экране проверки, а под ним показано
назначение целиком и его длина — ровно то, что уйдёт в файл.

### Плательщик по счетам

Пачку легко загрузить не под той организацией: сорок счетов на ООО под
плательщиком-ИП. Каждый парсер помечает «выставлен не нам», но лечить их
по одному бессмысленно. Сервис считает, чей ИНН стоит в графе «Покупатель»
чаще всего, и если это не выбранный плательщик, предлагает:

- **переназначить пачку** одной кнопкой — если такой плательщик заведён
  (при нескольких счетах выбирается, с какого платить). Пачка разбирается
  заново: замечания, дубли и подстановки зависят от того, кто платит;
- **завести плательщика** — если его нет: форма открывается с заполненными
  наименованием, ИНН и КПП из счетов, остаётся дописать банковские реквизиты.
  После сохранения возвращает к пачке, где уже есть кнопка «переназначить».

Один чужой счёт среди своих предложения не вызывает — это отдельный счёт,
а не ошибка пачки.

### Чужой счёт не уходит в файл

Разбор сверяет ИНН покупателя в счёте с ИНН выбранного плательщика. Счёт,
выставленный на другую организацию, помечается «выставлен не нам» и в файл
не попадает — пусть бухгалтер загрузит его под нужным плательщиком.

Замечания парсера и контрольные суммы хранятся раздельно: контрольные суммы
после подстановки из справочника пересчитываются, а замечания парсера должны
пересчёт пережить. Однажды они терялись, и 49 счетов ООО «ТЕТРАКОМ», загруженных
под плательщиком-ИП, ушли в файл для банка как чистые.

Если у одного ИНН в справочнике оказалось два расчётных счёта, строки помечаются.
Обычно это законно, но смена реквизитов «в письме от контрагента» — классическая
схема мошенничества, и такой случай стоит проверить звонком.

## Установка на Windows-сервер

Ниже — по частям, чтобы понимать, из чего установка состоит. Если нужно просто
вынести сервис на сервер и раздать людям, есть готовый путь со скриптами:
[razvertyvanie/README.md](../razvertyvanie/README.md).

### 1. Python и зависимости

Поставьте Python 3.11 или новее (галочка «Add python.exe to PATH»), затем:

```bat
cd C:\pp-bank
pip install -r servis\requirements.txt
```

### 2. Распознавание сканов и фото

На Windows основной движок — **встроенный `Windows.Media.Ocr`**, ставить ничего
не нужно. Он оказался точнее на реальных счетах (33 ключевых поля из 40 против
24 у Tesseract): аккуратнее обходится с рамками таблиц. Фото перед распознаванием
увеличивается до ~2500 px по короткой стороне: на снимке с телефона шапка
с реквизитами иначе не читается.

Если первый движок не сошёлся по контрольным суммам, счёт читается вторым,
и результат **склеивается по полям**: недостающее или не прошедшее контрольную
сумму берётся из другого движка, если там оно сумму проходит. В заметках
к счёту видно, что и откуда взято.

**Tesseract** нужен как второй движок — им перепроверяются счета, не прошедшие
контрольные суммы, — и как единственный, если сервис поедет на Linux.

```bat
winget install --id UB-Mannheim.TesseractOCR -e
```

Русского языка в установщике нет. Файл `rus.traineddata` лежит в проекте,
в папке `2-raspoznavanie/tessdata/` — сервис находит его сам и передаёт движку
явным путём. Класть язык в `Program Files` не нужно: туда нельзя писать без
прав администратора, а служба на сервере обычно работает под ограниченной
учётной записью.

Если языковые данные лежат в другом месте, путь задаётся переменной `PP_TESSDATA`.

Проверка: `python -c "from parser import ocr; print(ocr.dostupnye_dvizhki())"`
из папки `2-raspoznavanie`.

### 3. Вторая ступень распознавания (необязательно)

Счета, не прошедшие контрольные суммы после Tesseract, можно отправлять на
распознавание vision-модели. Это единственное место, где документ уходит за
пределы сервера, поэтому ступень выключена по умолчанию.

```bat
setx /M PP_VISION 1
setx /M ANTHROPIC_API_KEY sk-ant-...
```

Ключ берётся в консоли Anthropic. Платится только за те счета, которые не
осилил локальный движок.

### 4. Первый администратор

Откройте сервис в браузере — он сам предложит страницу «Первый запуск»
и заведёт администратора. Название организации не спрашивается.

Если графики на сервере нет, то же самое из командной строки:

```bat
python -m servis.nastroyka
```

Пароль — от 8 знаков. Страница «Первый запуск» работает ровно один раз: как
только появился первый пользователь, она отдаёт на обычный вход — иначе на
работающем сервисе любой прохожий сделал бы себя администратором.

### 5. Служба Windows

Чтобы сервис поднимался сам после перезагрузки, зарегистрируйте его службой.
Проще всего [NSSM](https://nssm.cc/):


### 6. HTTPS

**Сервис нельзя выставлять в интернет по голому HTTP.** Через него ходят пароли
и банковские реквизиты, а кука сессии выдаётся с флагом `secure` — по HTTP
браузер её не вернёт, и войти не получится.

Поставьте перед сервисом обратный прокси с сертификатом — IIS с ARR, nginx или
[Caddy](https://caddyserver.com/) (сам получает сертификат Let's Encrypt):

```
scheta.vashdomen.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Сам сервис при этом слушает только `127.0.0.1` и снаружи недоступен.

### 7. Резервные копии

Всё, что нужно сохранять, лежит в `servis\dannye`:

| Что | Зачем |
|---|---|
| `servis.db` | пользователи, плательщики, **нумерация платёжек**, журнал |
| `sekret.key` | ключ подписи форм |
| `zagruzki\` | исходные счета |
| `vygruzki\` | сформированные файлы для банка |

Главное — `servis.db`. Потеря журнала нумерации означает, что счётчик начнётся
заново и в банк уйдут платёжки с уже использованными номерами.

Копировать базу лучше средствами SQLite, а не простым копированием файла:

```bat
sqlite3 C:\pp-bank\servis\dannye\servis.db ".backup 'D:\backup\servis-%date%.db'"
```

## Тесты

```bat
python -m unittest discover -s servis\tests        :: 86 проверок сервиса
python -m unittest discover -s 2-raspoznavanie\tests
python -m unittest discover -s 1-vygruzka-v-bank\tests
```

Сервисные тесты подменяют базу и папки на временные — рабочие данные не трогают.

**Настоящие файлы, а не подменённые строки.** Большинство проверок разбора
платёжки подставляют готовые строки вместо чтения документа — это удобно, но
ошибка с разрядкой цифр жила ровно в подменённом шаге и потому не ловилась.
Поэтому в `tests/obraztsy/` лежат три настоящих PDF формы 0401060 с одинаковыми
реквизитами и разной вёрсткой: в первом цифры идут подряд, во втором разнесены
по клеткам бланка, в третьем ещё и подписи клеток оторваны от значений. Тест сначала убеждается, что образец **воспроизводит
поломку**, и только потом проверяет разбор — иначе образец ничего не стоит.
Пересоздать: `python servis/tests/obraztsy/sdelat.py`.
